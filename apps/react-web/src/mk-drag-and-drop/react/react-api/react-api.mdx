# React API

`@mk-drag-and-drop/react` is a view adapter over the DOM runtime. It forwards
completed lifecycle events unchanged and re-exports DOM public types rather
than redefining them.

## Imports and re-exports

```tsx
import {
  DragProvider,
  useDraggable,
  useDroppable,
  useDropContainer,
  useSortable,
  useDragHandle,
  useRemeasureDropTargets,
  useRecomputeActiveDrag,
  useRemeasureOverlay,
  composeRefs,
  centerToCenter,
  pointerToCenter,
  lockToXAxis,
  lockToYAxis,
  restrictToContainer,
  type DragProviderProps,
  type DragUpdateEvent,
  type SortablePreview,
  type SortableDropPlacement,
} from "@mk-drag-and-drop/react";
```

## Provider

### `DragProvider`

```tsx
<DragProvider
  pointerConfiguration={{ activationDelay: 180, activationDistance: 6 }}
  onDragUpdate={(event) => routeByGroup(event.group, event)}
>
  {children}
</DragProvider>
```

One provider creates one scope. Hooks use the nearest provider. Nested
providers are isolated scopes, not a coordinated drag feature. Use one provider
and multiple groups for document blocks, table rows, table columns, and
reference sortables.

### `DragProviderProps`

```ts
type DragProviderProps = DragLifecycleCallbacks & {
  children: ReactNode;
  announcements?: DragAnnouncements;
  dragOverlay?: (input: DragOverlayInput) => ReactNode;
  keyboardConfiguration?: KeyboardConfiguration;
  modifiers?: readonly DragModifierInput[];
  overlayRelease?: OverlayReleaseMode;
  pointerConfiguration?: PointerConfiguration;
  targetingAlgorithm?: TargetingAlgorithm;
  targetingConstraint?: TargetingConstraint;
};
```

Lifecycle callbacks receive the DOM package event and helpers unchanged.
Provider-wide pointer and keyboard configuration applies consistently to all
draggables in the scope.

### Announcements

```ts
type DragAnnouncements = {
  onDragStart?: (event: DragStartEvent) => string | null;
  onDragUpdate?: (event: DragUpdateEvent) => string | null;
  onDragEnd?: (event: DragEndEvent) => string | null;
  onDrop?: (event: DropEvent) => string | null;
};
```

Announcements receive group-bearing lifecycle events, including
`sortablePreview` on updates. Update announcements run only when
`activeDropTargetId` changes.

## Overlay

```ts
type DragOverlayInput = {
  dragState: DragState;
} & (
  | {
      phase: "dragging";
      remeasureOverlay: () => void;
      removeOverlay?: never;
    }
  | {
      phase: "released";
      remeasureOverlay: () => void;
      removeOverlay: () => void;
    }
);
```

`DragState` includes the captured group, source/pointer rects, current pointer,
active/previous target IDs, and completed sortable preview. Overlay content can
be selected exhaustively by group:

```tsx
dragOverlay={({ dragState }) => {
  switch (dragState.group) {
    case "table-rows":
      return <div className="blankOverlay blankOverlay--row" />;
    case "table-columns":
      return <div className="blankOverlay blankOverlay--column" />;
    default:
      return <div className="blankOverlay" />;
  }
}}
```

The wrapper is pointer-inert and begins at the registered source rect, not the
dimensions of a thin descendant handle. Sortable operation does not require an
overlay. A configured callback returning `null` is no overlay, not a measurable
blank one. `OverlayReleaseMode` is `"auto" | "manual"`.

## Draggable hook

### `useDraggable`

```ts
type UseDraggableOptions = {
  draggableId: string;
  group?: string;
};

type UseDraggableResult<E extends HTMLElement = HTMLElement> =
  HTMLAttributes<E> & { ref: RefCallback<E> };
```

```tsx
function Item({ id }: { id: string }) {
  const draggable = useDraggable<HTMLDivElement>({
    draggableId: id,
    group: "blocks",
  });
  return <div {...draggable}>Item</div>;
}
```

The result supplies a ref and pointer behavior, plus keyboard props when
keyboard dragging is enabled.

## Droppable hook

```ts
type UseDroppableOptions = {
  dropTargetId: string;
  group?: string;
  containerId?: string | null;
};

type UseDroppableResult<E extends HTMLElement = HTMLElement> =
  HTMLAttributes<E> & { ref: RefCallback<E> };
```

`useDroppable` registers the current ref and releases/re-registers safely over
React ref and effect lifecycles.

## Drop container hook

```ts
type UseDropContainerOptions = {
  containerId: string;
  group?: string;
};

type UseDropContainerResult<E extends HTMLElement = HTMLElement> = {
  ref: RefCallback<E>;
};
```

Use containers for cross-container and empty-list placement.

## Sortable hook

```ts
type UseSortableOptions = {
  draggableId: string;
  group?: string;
  containerId?: string | null;
  axis?: SortableAxis;
  placementBoundary?: SortablePlacementBoundary;
};

type UseSortableResult<E extends HTMLElement = HTMLElement> =
  HTMLAttributes<E> & { ref: RefCallback<E> };
```

```tsx
function SortableItem({ id }: { id: string }) {
  const sortable = useSortable<HTMLLIElement>({
    draggableId: id,
    group: "items",
    axis: "vertical",
    placementBoundary: { start: 0.25, end: 0.75 },
  });
  return <li {...sortable}>{id}</li>;
}
```

`SortableAxis` is `"vertical" | "horizontal"`.
`SortablePlacementBoundary` has optional `start` and `end` ratios.

## Drag handle hook

```ts
type UseDragHandleResult<E extends HTMLElement = HTMLElement> =
  HTMLAttributes<E> & { "data-dnd-drag-handle": string };
```

```tsx
const handle = useDragHandle<HTMLButtonElement>();
return (
  <button {...handle} type="button">
    Menu
  </button>
);
```

A button handle starts pointer dragging, but interactive filtering preserves
Space/Enter for the button. Use a noninteractive keyboard handle or explicit
commands for keyboard sorting. Quick pointer release remains a click; an
activated drag suppresses its one related generated click only.

## Remeasurement and recompute hooks

```ts
const remeasureDropTargets = useRemeasureDropTargets();
const recomputeActiveDrag = useRecomputeActiveDrag();
const remeasureOverlay = useRemeasureOverlay();

remeasureDropTargets({ group });
recomputeActiveDrag();
```

`useRemeasureDropTargets()` returns
`(input?: RemeasureDropTargetsInput) => void`.
`useRecomputeActiveDrag()` and `useRemeasureOverlay()` return `() => void`.

Remeasurement updates cached geometry but emits no update. Recompute uses the
last raw pointer and the normal modifier, preview, normalization, and
publication pipeline; it does not implicitly remeasure. Schedule the pair
after visible projection or scrolling reaches the DOM, compare orders, allow
only one pending frame, and do not loop on unchanged projection.

## Lifecycle and sortable types

React re-exports the exact DOM identities:

```ts
type SortablePreview =
  | { status: "inactive" }
  | { status: "source"; placement: SortableDropPlacement }
  | { status: "projected"; placement: SortableDropPlacement };

type SortableDropPlacement = {
  sourceContainerId: string | null;
  containerId: string | null;
  previousDraggableId: string | null;
  nextDraggableId: string | null;
  targetDraggableId: string | null;
  side: "before" | "after" | null;
};
```

- `inactive`: plain drag or invalid sortable source in the captured group.
- `source`: normalized preview equals captured source anchors.
- `projected`: normalized preview differs, including retained no-target and
  container-only projections.

`DragStartEvent`, `DragUpdateEvent`, `DragEndEvent`, `DropEvent`, and
`ActiveDragResetEvent` all carry the captured immutable `group`.
`DragUpdateEvent.sortablePreview` is published after package preview mutation.
Final placement uses the same normalizer; source/no-op drops omit it.

Route by group, not ID:

```tsx
onDragUpdate={(event) => {
  switch (event.group) {
    case "document-blocks":
      break;
    case "table-rows":
      break;
    case "table-columns":
      break;
  }
}}
```

Cancellation has no final artificial update. End consumer projection from
`onDragEnd`; retain successful projection until `onDrop` commits because end
precedes drop.

## Modifiers

React exports `lockToXAxis` and `lockToYAxis` unchanged. Its
`restrictToContainer` accepts `ReactRestrictToContainerInput`, allowing a ref
or resolver appropriate to React. Modifier types are re-exported from DOM.

## Targeting

The package exports:

- `pointerToCenter`
- `pointerToRectDistance`
- `centerToCenter`
- `getDistanceToRect`
- `maxPointerDistanceToRect`
- `maxOverlayCenterDistanceToRect`
- `TargetingAlgorithm`, `TargetingAlgorithmInput`
- `TargetingConstraint`, `TargetingConstraintInput`
- `DropTarget`

Targeting selects a candidate. Sortable placement and hysteresis remain
package-owned and must not be reconstructed from the pointer or active target.

## Input configuration

```ts
type PointerConfiguration = {
  activationDelay?: number | null;
  activationDistance?: number | null;
};
```

Delay and distance use OR semantics. Either threshold activates.

`KeyboardConfiguration` supports `enabled`, start/drop/cancel commands,
direction commands, and move distance. `KeyboardCommand` is a string or
readonly string array. Defaults use Space/Enter, Escape, and arrow keys.

## Geometry

`DragPoint` contains `x` and `y`. `DragRect` contains `x`, `y`, `left`, `top`,
`right`, `bottom`, `width`, and `height`. Overlay state also re-exports
`DragState` and `DragOverlayPhase` from the integration contract.

## Ref and element typing

All element hooks accept an `HTMLElement` generic:

```tsx
const sortable = useSortable<HTMLTableRowElement>({ draggableId: "row-1" });
```

Use `composeRefs` when the package callback ref and an application ref must
observe the same node:

```tsx
const ref = composeRefs(sortable.ref, localRef);
return <div {...sortable} ref={ref} />;
```

## Carrier-backed tables

A logical column spans multiple table parents, so one content element cannot
represent it. Keep transparent row/column carriers in separate normal-flow
lanes and separate groups. Project visible rows/cells from
`DragUpdateEvent.sortablePreview`, keep canonical arrays unchanged during
preview, and commit normalized placement once in `onDrop`.

See [Carrier-backed table sorting](/mk-drag-and-drop/examples/carrier-table).
