# React sortable

`useSortable` registers one element as both draggable and sortable. The package
owns transient sortable DOM movement. Applications consume normalized live
placement only when related presentation, such as a table column, must move
outside that sortable element.

## Minimal sortable list

```tsx
import { DragProvider, useSortable } from "@mk-drag-and-drop/react";

function SortableItem({ id }: { id: string }) {
  const sortable = useSortable<HTMLLIElement>({
    draggableId: id,
    group: "items",
  });
  return <li {...sortable}>{id}</li>;
}

function List({ ids }: { ids: readonly string[] }) {
  return (
    <DragProvider>
      <ul>
        {ids.map((id) => (
          <SortableItem key={id} id={id} />
        ))}
      </ul>
    </DragProvider>
  );
}
```

Use one provider and distinct groups for interaction boundaries and lifecycle
routing.

## Options and return value

```ts
type UseSortableOptions = {
  draggableId: string;
  group?: string;
  containerId?: string | null;
  axis?: "vertical" | "horizontal";
  placementBoundary?: { start?: number; end?: number };
};

type UseSortableResult<E extends HTMLElement = HTMLElement> =
  HTMLAttributes<E> & { ref: RefCallback<E> };
```

`draggableId` identifies the logical item. `group` controls compatibility and
routing. `containerId` describes ownership. Axis defaults to vertical.
Boundary ratios control initial movement and reversal hysteresis. Spread the
result onto the registered element, which must stay connected while relevant
to an active drag. Do not encode row/column meaning in the ID.

## Provider setup

```tsx
<DragProvider
  targetingAlgorithm={centerToCenter}
  pointerConfiguration={{ activationDelay: 180, activationDistance: 6 }}
  onDragUpdate={(event) => routePreview(event.group, event)}
  onDragEnd={(event) => endProjection(event.group, event.result)}
  onDrop={(event) => commitPlacement(event.group, event)}
>
  {children}
</DragProvider>
```

Activation delay and distance use OR semantics: either threshold activates.

## Targeting versus placement

Targeting selects an active compatible element. Placement applies axis,
boundary, direction, and reversal hysteresis. Applications must not derive
before/after from `activeDropTargetId`, inspect carrier DOM order, measure
midpoints, or reproduce package hysteresis.

## Live preview

```ts
type SortablePreview =
  | { status: "inactive" }
  | { status: "source"; placement: SortableDropPlacement }
  | { status: "projected"; placement: SortableDropPlacement };
```

| Status      | Meaning                                                                                      |
| ----------- | -------------------------------------------------------------------------------------------- |
| `inactive`  | Plain drag or source no longer registered as sortable in the captured group.                 |
| `source`    | Normalized package preview equals captured source order.                                     |
| `projected` | Preview differs, including cross-container, container-only, and retained no-target movement. |

`source` includes initial position, valid no-op, and returning to original
container/anchors. Its target/side are null. `projected` can remain after
leaving targets because package DOM retains its moved preview.

```text
select target
→ mutate package sortable DOM
→ normalize and classify
→ publish DragUpdateEvent
```

## Applying normalized placement

```ts
function getProjectedOrder(
  canonicalOrder: readonly string[],
  event: DragUpdateEvent,
): readonly string[] {
  if (event.sortablePreview.status !== "projected") {
    return canonicalOrder;
  }

  return applySortablePlacement(
    canonicalOrder,
    event.draggableId,
    event.sortablePreview.placement,
  );
}
```

The application helper removes the dragged ID and consumes target/side or
previous/next anchors. It never inspects pointer geometry, active target,
direction, midpoint, or carrier DOM.

## Canonical versus projected state

```tsx
const [canonicalColumns, setCanonicalColumns] = useState(initialColumns);
const [projectedColumns, setProjectedColumns] = useState(initialColumns);
const [commitCount, setCommitCount] = useState(0);

<DragProvider
  onDragUpdate={(event) => {
    if (event.group === "table-columns") {
      setProjectedColumns(getProjectedOrder(canonicalColumns, event));
    }
  }}
  onDragEnd={(event) => {
    if (event.group === "table-columns" && event.result !== "dropped") {
      setProjectedColumns(canonicalColumns);
    }
  }}
  onDrop={(event) => {
    if (event.group === "table-columns" && event.sortablePlacement) {
      setCanonicalColumns((current) =>
        applySortablePlacement(
          current,
          event.draggableId,
          event.sortablePlacement!,
        ),
      );
      setCommitCount((count) => count + 1);
    }
    clearProjection(event.group);
  }}
>
  <ProjectedTable columns={projectedColumns} />
</DragProvider>;
```

`onDragEnd` occurs before `onDrop`. Retain successful projection until drop
commits to avoid a canonical flash. Cancellation, no-target, and invalid-target
clear projection immediately. Preview state is presentation, not a document
transaction.

## Final placement and commit

```ts
type SortableDropPlacement = {
  sourceContainerId: string | null;
  containerId: string | null;
  previousDraggableId: string | null;
  nextDraggableId: string | null;
  targetDraggableId: string | null;
  side: "before" | "after" | null;
};
```

Live and drop placement share one normalizer. Source/no-op drops omit
`sortablePlacement`. Commit exactly once and only in `onDrop`.

## Containers and empty lists

```tsx
const container = useDropContainer<HTMLUListElement>({
  containerId: column.id,
  group: "cards",
});

const sortable = useSortable({
  draggableId: card.id,
  containerId: column.id,
  group: "cards",
});
```

Container-only placement represents empty/whitespace placement with null
target/side and descriptive container/sibling anchors.

## Axis and placement boundaries

Use vertical for rows/lists and horizontal for columns/toolbars. Matching
carrier/reference cases need the same dimensions, axis, targeting, constraint,
activation settings, and boundaries.

```tsx
useSortable({
  draggableId: id,
  placementBoundary: { start: 0.25, end: 0.75 },
});
```

Boundaries are current-target ratios and support unequal item dimensions.
Reversal retains prior placement until its configured boundary is crossed.

## Descendant drag handles

```tsx
function RowCarrier({ id }: { id: string }) {
  const sortable = useSortable({ draggableId: id, group: "table-rows" });
  const handle = useDragHandle<HTMLButtonElement>();

  return (
    <div {...sortable} className="rowCarrier">
      <button {...handle} type="button" aria-label={`Row ${id} menu`}>
        ⋮
      </button>
    </div>
  );
}
```

The button must descend from the carrier. Quick click activates its menu. Once
pointer drag activates, the package suppresses that interaction's generated
click; the next intentional click works.

Interactive filtering preserves Space/Enter for button activation, so the
button does not start keyboard dragging. Use a noninteractive/separate handle
or explicit commands for keyboard sorting. Editable descendants stay
protected.

## Optional group-specific overlays

Sortable operation does not require an overlay. Pointer targeting works without
one; rect targeting needs a measurable overlay.

```tsx
dragOverlay={({ dragState }) => {
  switch (dragState.group) {
    case "table-rows":
      return <div className="blankOverlay blankOverlay--row" />;
    case "table-columns":
      return <div className="blankOverlay blankOverlay--column" />;
    default:
      return <div className="blankOverlay" />;
  }
}}
```

Return a real blank element rather than `null`. The pointer-inert wrapper starts
at the full carrier rect, so a thin button does not create a thin drag
footprint.

## Remeasure and recompute

```tsx
const remeasureDropTargets = useRemeasureDropTargets();
const recomputeActiveDrag = useRecomputeActiveDrag();
const frameRef = useRef<number | null>(null);

function scheduleGeometrySync(group: string) {
  if (frameRef.current !== null) return;
  frameRef.current = requestAnimationFrame(() => {
    frameRef.current = null;
    remeasureDropTargets({ group });
    recomputeActiveDrag();
  });
}
```

Run after projected DOM or actual scrolling changes. Remeasurement updates
cached geometry. Recompute uses the last raw pointer and publishes through the
same modifier/preview/normalization path; it does not measure implicitly.
Compare projected orders, allow one frame, and cancel it on end/unmount.

## Cancel and cleanup

Escape and pointer cancellation restore package preview DOM and publish a
canceled ending without drop or artificial final update. Provider unmount
silently releases runtime resources; hook effects release registrations and
applications cancel their own pending frames.

The DOM `DragController.cancelDrag()` method is for high-level Vanilla teardown.
React provider unmount retains its component-lifecycle release behavior.

## Performance

- Keep stable keyed carrier elements mounted.
- Do not reconcile package-owned carrier order from canonical state mid-drag.
- Consume neighboring normalized anchors instead of scanning all items.
- Remeasure a group only after actual layout/scroll changes.
- Keep a virtualized source carrier mounted during its active drag.
- Built-in targeting narrows candidates; custom algorithms retain full scans.

## Common mistakes

- Committing canonical arrays in `onDragUpdate`.
- Calculating side from pointer or `activeDropTargetId`.
- Reading package-mutated carrier DOM.
- Routing from ID prefixes.
- Adding providers merely to separate rows and columns.
- Pinning every carrier to an immutable absolute coordinate.
- Returning `null` for a desired measurable blank overlay.
- Treating an interactive button as a keyboard drag handle.
- Recomputing without remeasurement after layout changes.
- Clearing successful projection before `onDrop`.

## Carrier-backed tables

A logical column spans headers and cells under different row parents, so it
cannot be one table-content sortable. Use:

- one row carrier per logical row;
- one column carrier per logical column;
- separate row/column groups;
- absolute overlay lanes with normal flex/grid-flow children;
- transparent carriers with pointer-enabled descendant buttons;
- visible rows/cells rendered from projected order;
- canonical state committed once in `onDrop`.

Fixed-position individual carriers can change DOM anchors without changing
geometry and break parity. Carrier geometry must reflow with package DOM order.
Table/editor content stays outside carriers.

See the runnable [Carrier-backed table sorting example](/mk-drag-and-drop/examples/carrier-table),
which compares ordinary vertical and horizontal sortables.
