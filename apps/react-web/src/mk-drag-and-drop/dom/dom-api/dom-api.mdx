# DOM API

Use the package root for application code. The `/integration` entry point is
for framework adapters. Applications must not import runtime registries or
package-private modules.

## Controller

### `createDragController`

```ts
function createDragController(options?: DragControllerOptions): DragController;
```

One controller creates one drag-and-drop scope. Use groups inside that scope to
separate document blocks, table rows, table columns, and other interactions.
The group is captured when activation succeeds and stays stable for the drag.

### `DragControllerOptions`

```ts
type DragControllerOptions = DragLifecycleCallbacks & {
  announcements?: DragControllerAnnouncements;
  dragOverlay?: (input: DragControllerOverlayInput) => HTMLElement | null;
  keyboardConfiguration?: KeyboardConfiguration;
  modifiers?: readonly DragModifierInput[];
  overlayRelease?: OverlayReleaseMode;
  overlayRoot?: HTMLElement;
  pointerConfiguration?: PointerConfiguration;
  targetingAlgorithm?: TargetingAlgorithm;
  targetingConstraint?: TargetingConstraint;
};
```

Pointer and keyboard configuration applies to the whole controller scope.

### Announcements

```ts
type DragControllerAnnouncements = {
  onDragStart?: (event: DragStartEvent) => string | null;
  onDragUpdate?: (event: DragUpdateEvent) => string | null;
  onDragEnd?: (event: DragEndEvent) => string | null;
  onDrop?: (event: DropEvent) => string | null;
};
```

Announcements receive the same group-bearing events as lifecycle callbacks.
Update announcements run when the active target changes.

### `DragController`

```ts
type DragController = {
  cancelDrag: () => void;
  remeasureDropTargets: (input?: RemeasureDropTargetsInput) => void;
  remeasureOverlay: () => void;
  recomputeActiveDrag: () => void;
};
```

`cancelDrag()` is safe while idle and cancels pending pointer activation.
During an active pointer or keyboard drag it publishes the existing canceled
ending, restores sortable DOM, clears active input/overlay state, and never
calls `onDrop` or manufactures another update. The controller remains reusable.
Call it before a Vanilla mount removes DOM it owns:

```ts
return () => {
  controller.cancelDrag();
  root.replaceChildren();
};
```

## Sortable

### `createSortable`

```ts
type CreateSortableInput = {
  controller: DragController;
  element: HTMLElement;
  draggableId: string;
  group?: string;
  containerId?: string | null;
  axis?: SortableAxis;
  placementBoundary?: SortablePlacementBoundary;
};

function createSortable(input: CreateSortableInput): void;
```

The registered element is draggable and sortable. Package-owned preview DOM
mutation completes before `DragUpdateEvent` publication.

### Axis and boundaries

```ts
type SortableAxis = "vertical" | "horizontal";

type SortablePlacementBoundary = {
  start?: number;
  end?: number;
};
```

The default axis is vertical. Boundary ratios are clamped to `0..1`; defaults
are `0.25` and `0.75`. They control initial movement and reversal hysteresis.
Applications must not reproduce this decision from pointer coordinates or
`activeDropTargetId`.

### `SortablePreview`

```ts
type SortablePreview =
  | { status: "inactive" }
  | { status: "source"; placement: SortableDropPlacement }
  | { status: "projected"; placement: SortableDropPlacement };
```

| Status      | Meaning                                                                                                                                 |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `inactive`  | The source is not a valid sortable registration in the captured group. This includes plain draggables and invalidated sortable sources. |
| `source`    | Normalized preview order equals the captured source order: initial position, valid no-op, no movement, or returning to source.          |
| `projected` | Normalized preview differs: same/cross-container movement, container-only placement, or retained movement after leaving targets.        |

`inactive` does not mean merely “no target.” Source placement uses captured
source container/sibling anchors with null target and side.

### `SortableDropPlacement`

```ts
type SortableDropPlacement = {
  sourceContainerId: string | null;
  containerId: string | null;
  previousDraggableId: string | null;
  nextDraggableId: string | null;
  targetDraggableId: string | null;
  side: "before" | "after" | null;
};
```

One normalizer produces live and final placement. A projected drop without an
intervening update matches the last projected preview. Successful source/no-op
drops omit `sortablePlacement`. Container-only placement has null target/side
while container and sibling anchors remain descriptive.

## Drag handles

```ts
type CreateDragHandleInput = { element: HTMLElement };
function createDragHandle(input: CreateDragHandleInput): void;
```

The handle must descend from its draggable. A button may be a pointer handle,
but Space/Enter continue to activate that button; keyboard sorting needs a
noninteractive handle or explicit commands. Editable descendants remain
protected.

A quick pre-activation release remains a click. An activated pointer drag
suppresses only its related generated click in the initiating draggable
subtree. Later intentional and keyboard clicks remain available.

## Lifecycle

```ts
type DragSource = "pointer" | "keyboard";
type DragEndResult = "dropped" | "no-target" | "invalid-target" | "canceled";

type DragStartEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
  pointerPosition: DragPoint;
  sourceRect: DragRect;
};

type DragUpdateEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
  pointerPosition: DragPoint;
  overlayRect: DragRect | null;
  activeDropTargetId: string | null;
  previousDropTargetId: string | null;
  sortablePreview: SortablePreview;
};

type DragEndEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
  result: DragEndResult;
  overlayRect: DragRect | null;
  dropTargetId: string | null;
};

type DropEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
  dropTargetId: string;
  sortablePlacement?: SortableDropPlacement;
};

type ActiveDragResetEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
};
```

Registration changes may invalidate source/target but never change the
captured event group. Disconnected targets disappear from normalized anchors
on the next update or recompute.

```text
measure/select target
→ mutate package sortable preview
→ normalize and classify
→ publish DragUpdateEvent
```

```text
flush final pointer update
→ validate target
→ capture placement
→ restore package DOM
→ publish drag end
→ publish successful drop
```

Cancellation emits no artificial update. Package DOM is restored before public
end/drop callbacks. Invalid release reports `invalid-target` and skips `onDrop`.

## Overlays

```ts
type OverlayReleaseMode = "auto" | "manual";

type DragControllerOverlayInput =
  | {
      dragState: DragState;
      phase: "dragging";
      remeasureOverlay: () => void;
      removeOverlay?: never;
    }
  | {
      dragState: DragState;
      phase: "released";
      remeasureOverlay: () => void;
      removeOverlay: () => void;
    };
```

Sortable behavior does not require an overlay. Pointer targeting works without
one; rect-based targeting requires one. Return a real measurable blank element
for blank feedback—`null` means no overlay. The pointer-inert wrapper starts at
the full source rect, not a thin handle. Select row/column presentation using
`dragState.group`.

## Remeasurement, recompute, and cancellation

```ts
type RemeasureDropTargetsInput = { group?: string };

controller.remeasureDropTargets({ group });
controller.recomputeActiveDrag();
controller.remeasureOverlay();
controller.cancelDrag();
```

Remeasurement updates cached geometry without publishing. Recompute reuses the
last raw pointer, reapplies modifiers, and runs the normal preview,
normalization, and publication path without implicit measurement. After layout
or scroll changes, call them in that order after presentation reaches the DOM.
Compare projected order and deduplicate scheduled work to avoid loops.

## Targeting

Algorithms choose a target; sortable placement decides side and hysteresis.

- `pointerToCenter`
- `pointerToRectDistance`
- `centerToCenter`
- `getDistanceToRect`
- `maxPointerDistanceToRect({ maxDistance })`
- `maxOverlayCenterDistanceToRect({ maxDistance })`

```ts
type TargetingAlgorithm = (input: TargetingAlgorithmInput) => DropTarget | null;
type TargetingConstraint = (input: TargetingConstraintInput) => boolean;
```

Built-ins narrow candidates where safe. Custom algorithms retain full-scan
semantics.

## Input configuration

```ts
type PointerConfiguration = {
  activationDelay?: number | null;
  activationDistance?: number | null;
};

type KeyboardCommand = string | readonly string[];

type KeyboardConfiguration = {
  enabled?: boolean;
  start?: KeyboardCommand;
  drop?: KeyboardCommand;
  cancel?: KeyboardCommand;
  moveUp?: KeyboardCommand;
  moveDown?: KeyboardCommand;
  moveLeft?: KeyboardCommand;
  moveRight?: KeyboardCommand;
  moveDistance?: number;
};
```

Delay and distance use OR semantics: either threshold activates. Defaults are
Space/Enter to start/drop, Escape to cancel, arrows to move, and 24 pixels per
keyboard movement.

## Low-level integration API

```ts
import {
  createDragRuntimeScope,
  createDomDraggable,
  createDomDroppable,
  createDomDropContainer,
  createDomSortable,
  domDragHandleAttribute,
  type DragRuntimeScope,
  type DragRuntimeScopeConfigureInput,
  type DragRuntimeScopeOptions,
  type DragRuntimeSubscription,
  type ActiveDragResetEvent,
} from "@mk-drag-and-drop/dom/integration";
```

`createDragRuntimeScope` supplies adapter infrastructure: configuration,
registration, group measurement, overlays, cancellation, recompute, and
completed-event subscriptions. Subscribers are not a sortable-processing hook.

`DragRuntimeSubscription` contains start/update/end/drop/reset callbacks, all
with the captured group. The entry point also exports:

- DOM draggable behavior/input/runtime and pointer/key adapter event types.
- DOM droppable and container behavior/input/runtime types.
- DOM sortable behavior/input/runtime, axis, and boundary types.
- Drag state, overlay host/render/update/phase, and release types.
- `SortablePreview`, `ActiveDragResetEvent`, and `domDragHandleAttribute`.

It does not export the sortable registry or internal coordinator.
