# Targeting

Targeting selects one active registered target from the drag session's captured
group. Sortable placement is a later package-owned step; application code does
not calculate before/after from `activeDropTargetId`.

## Built-in algorithms

- `pointerToCenter` selects by pointer-to-target-center distance.
- `pointerToRectDistance` selects by distance to a target rectangle.
- `centerToCenter` selects by overlay-center-to-target-center distance and
  requires a non-null overlay rectangle.

Custom algorithms receive the filtered measured `dropTargets` and keep their
full-scan semantics. Sortable groups may narrow ordinary built-in candidate work
to relevant items, containers, and nearby siblings.

Constraints such as `maxPointerDistanceToRect` and
`maxOverlayCenterDistanceToRect` remove ineligible candidates before the
algorithm selects a winner.

```ts
const controller = createDragController({
  targetingAlgorithm: centerToCenter,
  targetingConstraint: maxOverlayCenterDistanceToRect({
    maxDistance: 120,
  }),
});
```

Use identical axis, item dimensions, algorithm, constraint, overlay geometry,
and pointer paths when comparing two sortable presentations.

## Targeting versus normalized placement

`DragUpdateEvent.activeDropTargetId` reports the selected target.
`DragUpdateEvent.sortablePreview` reports the package's completed normalized
sortable result after preview DOM movement:

```ts
if (event.sortablePreview.status === "projected") {
  renderProjectedOrder(
    applySortablePlacement(
      canonicalOrder,
      event.draggableId,
      event.sortablePreview.placement,
    ),
  );
}
```

Do not inspect pointer coordinates, target rectangles, direction, or midpoint
in this application helper. Do not infer side from the active target. The
sortable subsystem already accounts for same-target reversal hysteresis,
cross-container entry, dragged-item selection, and container-only targets.

No active target does not necessarily mean source or inactive. A moved preview
is retained after the pointer leaves valid targets and remains `projected`.
`inactive` instead means the source is not a valid sortable registration in the
captured group.

## Groups

Target candidates are isolated by the captured group. This allows one scope to
hold document blocks, table row carriers, and table column carriers without
cross-targeting. The same `event.group` routes lifecycle work. Registration
changes cannot change the captured event group.

## Stale targets

If a target disconnects, the next update or `recomputeActiveDrag()` normalizes
using surviving registered sibling/container anchors and never publishes the
stale target as an anchor. Releasing against the stale active target reports
`invalid-target` and does not call `onDrop`.

## Changed geometry

Use the explicit pair after scrolling or layout changes:

```ts
controller.remeasureDropTargets({ group });
controller.recomputeActiveDrag();
```

Remeasurement updates the cache only. Recompute reuses the last raw pointer,
reapplies modifiers, selects from current cached measurements, processes the
preview, normalizes, and publishes exactly one update. It performs no implicit
full-group measurement.
