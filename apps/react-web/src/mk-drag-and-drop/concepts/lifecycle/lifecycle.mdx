# Lifecycle

Lifecycle callbacks are the application boundary. The package owns input,
measurement, target selection, sortable DOM preview, normalization, and cleanup.
The application owns projected presentation and durable state.

## Public event types

```ts
type SortablePreview =
  | { status: "inactive" }
  | { status: "source"; placement: SortableDropPlacement }
  | { status: "projected"; placement: SortableDropPlacement };

type DragStartEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
  pointerPosition: DragPoint;
  sourceRect: DragRect;
};

type DragUpdateEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
  pointerPosition: DragPoint;
  overlayRect: DragRect | null;
  activeDropTargetId: string | null;
  previousDropTargetId: string | null;
  sortablePreview: SortablePreview;
};

type DragEndEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
  result: "dropped" | "no-target" | "invalid-target" | "canceled";
  overlayRect: DragRect | null;
  dropTargetId: string | null;
};

type DropEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
  dropTargetId: string;
  sortablePlacement?: SortableDropPlacement;
};

type ActiveDragResetEvent = {
  draggableId: string;
  group: string;
  source: DragSource;
};
```

`group` is captured when pointer or keyboard activation succeeds. It remains
stable for the complete session and is forwarded to lifecycle, announcement,
subscription, and reset callbacks. Re-registration can invalidate a source or
target, but cannot change that group.

## Update guarantee

Every normal drag update contains a completed `sortablePreview`. Conceptually:

```text
measure/select target
-> update package-owned sortable preview
-> normalize current preview
-> publish DragUpdateEvent
```

The public callback therefore observes placement after the package has mutated
its transient sortable DOM. Consumers may rely on the event, but not on carrier
DOM inspection, a private registry, or subscriber registration order.

| Status      | Meaning                                                                                                                                                                                                                                       |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inactive`  | A plain drag, or a source that is no longer a valid sortable registration in the captured group. No active target alone does not imply inactive.                                                                                              |
| `source`    | Normalized current order equals the source container and sibling anchors captured at activation. This includes initial position, no target before movement, a valid no-op, and returning to the original placement. Target and side are null. |
| `projected` | Normalized preview differs from source. This includes same-container, cross-container, container-only, and retained moved preview after leaving valid targets.                                                                                |

For container-only projected placement, `targetDraggableId` and `side` are null,
but `containerId`, `previousDraggableId`, and `nextDraggableId` still identify
the projected location. Disconnected targets are not published as stale
normalized anchors.

## End and drop ordering

For a release, the package guarantees:

```text
flush final pointer update
-> validate target
-> capture normalized placement
-> restore package preview DOM
-> publish onDragEnd
-> publish onDrop for a valid drop
```

`onDragEnd` always runs. `onDrop` runs only when `result` is `"dropped"`.
Because end precedes drop, retain a successful application projection until
`onDrop` commits. Clear projection immediately for `canceled`, `no-target`, and
`invalid-target`.

Cancellation does not produce an artificial final update. The package restores
its preview DOM before public end/drop handling. An invalid release reports
`invalid-target` and never calls `onDrop`.

Both live and final placement use one normalization path. When no update occurs
between a projected event and release, `DropEvent.sortablePlacement` equals the
last projected placement. A successful source/no-op drop omits placement.

```ts
const controller = createDragController({
  onDragUpdate(event) {
    if (event.group === "table-columns") {
      projectedColumns = getProjectedOrder(canonicalColumns, event);
      renderTable();
    }
  },
  onDragEnd(event) {
    if (event.result !== "dropped") clearProjection(event.group);
  },
  onDrop(event) {
    if (event.group === "table-columns" && event.sortablePlacement) {
      commitColumnsOnce(event.draggableId, event.sortablePlacement);
    }
    clearProjection(event.group);
  },
});
```

## Groups route lifecycle work

One scope may contain independent domains:

```ts
switch (event.group) {
  case "document-blocks":
    break;
  case "table-rows":
    break;
  case "table-columns":
    break;
}
```

Groups also restrict target interaction. Do not route by an id prefix and do
not encode row/column type information in `draggableId`.

## Remeasure and recompute

After scrolling or application-owned layout changes:

```ts
controller.remeasureDropTargets({ group });
controller.recomputeActiveDrag();
```

Remeasurement updates cached target geometry and publishes no event. Recompute
reuses the last raw pointer, reapplies modifiers, uses the current cache, and
runs the same preview/normalization/publication path. It does not perform an
implicit group remeasurement.

In React, use the public hooks:

```tsx
const remeasureDropTargets = useRemeasureDropTargets();
const recomputeActiveDrag = useRecomputeActiveDrag();

useLayoutEffect(() => {
  const frame = requestAnimationFrame(() => {
    remeasureDropTargets({ group });
    recomputeActiveDrag();
  });
  return () => cancelAnimationFrame(frame);
}, [group, remeasureDropTargets, recomputeActiveDrag]);
```

Schedule after visible projection reaches the DOM, compare the next order with
the current order, and deduplicate scheduled work to prevent update loops.
