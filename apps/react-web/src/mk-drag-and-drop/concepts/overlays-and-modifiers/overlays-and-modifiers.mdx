# Overlays and modifiers

An overlay is optional presentation and geometry managed by the drag scope.
Sortable behavior does not require one. Pointer-based targeting can work with
no overlay, while rect-based targeting such as `centerToCenter` requires an
overlay rectangle.

## Group-specific overlays

Overlay callbacks receive `dragState.group`. One provider/controller can render
different real blank elements for rows, columns, and document blocks:

```tsx
<DragProvider
  dragOverlay={({ dragState }) => {
    switch (dragState.group) {
      case "table-rows":
        return <div className="blankRowOverlay" aria-hidden="true" />;
      case "table-columns":
        return <div className="blankColumnOverlay" aria-hidden="true" />;
      default:
        return <div className="blankBlockOverlay" aria-hidden="true" />;
    }
  }}
>
  {children}
</DragProvider>
```

The package's wrapper is fixed-position and pointer-inert. Overlay content
should also remain pointer-inert. A row or column blank element may be larger
than a thin descendant handle because the source rectangle is measured from the
registered carrier, not the button.

Before returned content is measured, the runtime uses the translated source
rect. Returning `null` from a configured overlay callback is not equivalent to
returning a real measurable blank element.

## Measurement

The runtime caches overlay geometry and updates it when content is measured or
resized. `remeasureOverlay()` and React `useRemeasureOverlay()` refresh that
cache after application changes not covered by normal observation. An overlay
remeasure that recomputes the active drag follows the same completed sortable
preview and normalization sequence as pointer movement.

## Release

Default `overlayRelease="auto"` removes the overlay when the drag ends.
`"manual"` publishes a released render input with `removeOverlay` for an
application release animation. Lifecycle ordering and sortable DOM restoration
remain the same.

## Modifiers

Modifiers transform pointer-derived movement before overlay geometry, target
selection, and sortable processing. Built-ins include `lockToXAxis`,
`lockToYAxis`, and `restrictToContainer`.

`recomputeActiveDrag()` reuses the last raw pointer and reapplies modifiers. It
does not implicitly remeasure drop targets. After layout or scrolling changes:

```ts
controller.remeasureDropTargets({ group });
controller.recomputeActiveDrag();
```

See [Carrier-backed tables](/projects/mk-drag-and-drop/examples/carrier-table)
for row- and column-sized blank overlays with the same geometry as conventional
sortable parity controls.
