# Sortable

A sortable item is both a drag source and a drop target. The package selects a
target, moves package-owned preview DOM, and publishes a normalized placement.
Your application renders any separate visible projection and owns the durable
order.

## One placement representation

Live and final placement both use:

```ts
type SortableDropPlacement = {
  sourceContainerId: string | null;
  containerId: string | null;
  previousDraggableId: string | null;
  nextDraggableId: string | null;
  targetDraggableId: string | null;
  side: "before" | "after" | null;
};
```

`sourceContainerId` is captured at activation. Current container and neighboring
anchors come from the package-owned preview order, skipping other groups and
invalid registrations. Item targets retain exact target/side when valid.
Container-only placement has null target/side.

Every normal update has:

```ts
type SortablePreview =
  | { status: "inactive" }
  | { status: "source"; placement: SortableDropPlacement }
  | { status: "projected"; placement: SortableDropPlacement };
```

| Status      | Meaning                                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `inactive`  | The active source is plain or no longer a valid sortable in the captured group.                                                                        |
| `source`    | Current normalized container and anchors equal the activation snapshot. Initial, no-target-before-movement, no-op, and returned placements are source. |
| `projected` | Current normalized placement differs from source, including retained movement after leaving all valid targets.                                         |

Do not infer source/projected state from `activeDropTargetId`. Source equality is
normalized placement equality.

## Projection

```ts
function getProjectedOrder(
  canonicalOrder: readonly string[],
  event: DragUpdateEvent,
): readonly string[] {
  if (event.sortablePreview.status === "inactive") {
    return canonicalOrder;
  }

  if (event.sortablePreview.status === "source") {
    return canonicalOrder;
  }

  return applySortablePlacement(
    canonicalOrder,
    event.draggableId,
    event.sortablePreview.placement,
  );
}
```

`applySortablePlacement` may remove the dragged id, insert relative to exact
target/side, and fall back to previous/next anchors. It must not inspect pointer
coordinates, rectangles, carrier DOM, direction, midpoint, or hysteresis. The
package already made those decisions.

Keep canonical order unchanged during `onDragUpdate`. On `source`, render the
canonical order. On `projected`, render transient order. Commit once in
`onDrop`. Since `onDragEnd` runs before `onDrop`, retain a dropped projection
until the drop callback commits and clear it immediately for every non-dropped
result.

## Registration

DOM:

```ts
createSortable({
  controller,
  element,
  draggableId: row.id,
  group: "table-rows",
  containerId: "table-body",
  axis: "vertical",
  placementBoundary: { start: 0.25, end: 0.75 },
});
```

React:

```tsx
const sortable = useSortable<HTMLDivElement>({
  draggableId: column.id,
  group: "table-columns",
  containerId: "table-columns",
  axis: "horizontal",
  placementBoundary: { start: 0.25, end: 0.75 },
});

return <div {...sortable}>{column.label}</div>;
```

Use consistent axis and group among siblings. A drop container allows broad or
empty destination space. `placementBoundary` controls same-target reversal
hysteresis; the targeting algorithm still chooses the active target.

## Completion and invalidation

The update is published after preview DOM mutation and normalization. At drop,
the runtime flushes the final update, validates the target, captures normalized
placement, restores preview DOM, calls `onDragEnd`, and then calls `onDrop`.

Disconnected targets are removed from normalized anchors on the next update or
recompute. A disconnected source becomes inactive. Releasing against a stale
active target yields `invalid-target` and no drop. Cancellation restores package
DOM without an artificial last update.

## Geometry changes

```ts
controller.remeasureDropTargets({ group: "table-rows" });
controller.recomputeActiveDrag();
```

Remeasurement refreshes target rectangles; it publishes nothing. Recompute uses
the last raw pointer and current measurements, reapplies modifiers, and runs the
ordinary live placement path without implicit remeasurement. Schedule after
your projected layout commits and guard against repeated unchanged work.

## Carrier-backed tables

A logical table column spans many cells and cannot be represented by one table
content element. Use geometry carriers for the package-owned sortable preview
and `sortablePreview` for the separate visible table projection. Rows and
columns use independent groups and lanes.

See [Carrier-backed tables](/projects/mk-drag-and-drop/examples/carrier-table)
for the complete layout, lifecycle, React, and Vanilla architecture. The
ordinary vertical and horizontal examples there are parity references, not a
required production structure.
